协议概览
ICCOA 数字车钥匙 4.0 规范核心内容

本规范定义了数字车钥匙系统的完整技术方案，支持 BLE、NFC、UWB 三种短距通信协议，覆盖从证书体系、认证流程到控车指令的全链路。

📶

BLE 接口

基于 GATT Profile，Service UUID FCD1，支持标准认证与快速认证，MTU > 200 Bytes，广播周期 ≤ 100ms

🔐

证书体系

X.509 v3 格式，ECDSA-P256 算法，支持 CA 模式与非 CA 模式钥匙分享，证书大小控制在 700 字节内

📡

UWB 测距

符合 IEEE 802.15.4/z + FiRa 标准，厘米级精度，防中继攻击，支持无感解闭锁

🗝️

钥匙生命周期

包含开通、分享（车主/好友钥匙）、冻结、恢复、撤销、注销全流程，支持在线与离线场景

🚗

远程控车 RKE

支持门锁、车窗、后备箱、引擎、寻车等功能，带签名认证和持续控车两种模式

⌚

多设备支持

手机（Phone）与可穿戴（Wearable）均可作为钥匙载体，SE/TEE 作为安全存储

规范版本：本文件替代 ICCOA/T 002-2023（数字车钥匙 2.0），新增非 CA 模式分享钥匙、UWB 测距支持、远程控车功能。

BLE 配对流程
加密配对码广播 + CCCD 订阅触发首次认证
核心安全机制：车辆通过 AES-128-CTR 加密配对码后广播，只有持有 bleBroadcastKey 的合法设备才能解密并发起配对，防止未授权设备扫描连接。

完整配对流程

1

车辆生成明文配对码

每 30 秒随机生成十进制配对码（0 ~ 999999），转为 4 字节 Big-Endian 十六进制：plainPairingCode（0x00000000 ~ 0x000F423F）

2

生成 Nonce

随机生成 4 字节 IV，对 IV 求 SHA-256 后截取前 12 字节得到 Nonce（96位）

3

AES-128-CTR 加密

cipherPairingCode = AES_128_CTR(bleBroadcastKey, plainPairingCode, Nonce)
生成 4 字节密文配对码

4

构建广播数据

密文广播 = IV（4B）|| cipherPairingCode（4B），总 8 字节，放入 AD Data 字段广播

5

设备扫描与解密

设备扫描到符合规范的 RPA 广播，提取 pairingCode，使用本地 bleBroadcastKey + IV 解密验证，成功后主动发起配对请求

6

CCCD 订阅 → 触发首次标准交易

BLE 配对完成后，设备主动执行 CCCD 服务订阅（启用 DataOut Notification），车端收到后触发首次标准认证流程

注意：开通车主钥匙时，bleBroadcastKey 由服务器随钥匙证书一同下发给设备；其他场景（好友分享等）也通过服务器通道安全传输，不在 BLE 信道中明文传输。
钥匙认证流程
标准认证（首次必须）与快速认证（后续可用）

标准认证（Standard Auth）

基于完整 ECDH 密钥协商 + 证书链验证，车辆验证设备持有有效数字钥匙证书。首次必须执行，是快速认证的前提。

安全级别高 耗时较长

快速认证（Fast Auth）

利用上次标准认证建立的共享会话状态进行轻量认证，省去证书传输步骤。若快速认证失败，自动回退标准认证。

低延迟 依赖标准认证

标准认证关键步骤

认证基于 APDU 命令接口（Type = 0x00），通过 DataIn（FFF1 Write）发送命令，DataOut（FFF2 Notification）接收响应。

①

设备发起：SELECT + 证书 CSR

设备 DKF 发送 SELECT APDU 选中数字车钥匙 Applet，附带设备临时公钥（ECC P-256）

②

车辆回应：车证书 + 挑战随机数

车辆发送自身证书（vehicleCert）和 16 字节车端随机数（8A tag），供设备验证车辆身份并计算签名

③

设备回应：数字钥匙证书 + ECDH + 签名

设备发送 ownerDkCert（或 sharedDkCert），附带设备临时公钥和认证数据。车辆验证证书链和签名有效性

④

车辆认证通过 → 建立会话密钥

双方通过 ECDH 派生共享会话密钥，后续控车指令使用此密钥进行 MAC 保护

快速认证触发条件：
  • 必须完成过至少一次成功的标准认证
  • 快速认证失败后，应重新执行标准认证
  • 车企可自定义策略（如超过 7 天未使用则强制标准认证）
  • 自定义策略不得与上述两条规则冲突

实现方案与设计
工程落地的分层架构与关键模块设计

分层架构

应用层

车 App / Native App

调用 DKF API 实现 UI 交互：开通、分享、控车、状态展示。不直接操作 BLE。

框架层

DKF（数字钥匙框架）

封装 BLE 连接管理、APDU 处理、测距控制、状态机管理。对上提供 API，对下与 TEE/SE 通信。

安全层

TEE TA / SE Applet

持有数字钥匙私钥，在安全环境中完成 ECDSA 签名、ECDH 密钥协商、AES 加解密。私钥不出 TEE/SE。

通信层

BLE Stack

管理扫描（Central 角色）、GATT 连接、MTU 协商（>200B）、数据收发分包、重传机制。

手机端关键模块设计

BLE 扫描与连接管理
  • 背景扫描占空比 ≥ 10%，过滤 Service UUID = 0xFCD1 的广播
  • 扫描到广播后，解析 AD Data 中的 pairingCode 密文，使用 bleBroadcastKey 解密
  • 解密成功则将该设备加入候选列表，按 RSSI 排序
  • RPA 地址解析：使用预存 IRK 对 RPA 进行解析，确认为已配对车辆
  • MTU 协商：连接后立即发起 MTU 请求，目标 512B（最大 BLE 5.0 支持）
  • CCCD 订阅：发现 FFF2 特征后立即写入 CCCD 启用 Notification
认证状态机
  • IDLE → BLE 连接建立 + CCCD 订阅 → CONNECTING
  • CONNECTING → 车端触发认证请求 → STANDARD_AUTH
  • STANDARD_AUTH → 认证通过 → AUTHENTICATED
  • AUTHENTICATED → 断连 → IDLE（保留 fast auth 上下文）
  • 快速认证失败 → 回退 STANDARD_AUTH
  • 任意状态 → BLE 断连 → IDLE
数据帧收发与分包
  • 发送：构建完整帧（Version + Type + Status + Length + Data），按 MTU 大小分包，逐包发送
  • 接收：按帧头 Length 字段拼包，组装完整帧后回调上层
  • 超时机制：发送后 3 秒内未收到响应，触发重试或错误回调
  • Write with Response：等待 ATT ACK 后再发送下一包，防止丢包
钥匙存储设计
  • 私钥：存储在 SE（安全单元）或 TEE KeyStore，不可导出
  • 证书链（ownerDkCert / vehicleCert / midShareCert）：加密存储在 TEE 或 SE Applet
  • bleBroadcastKey、IRK：加密存储，TEE 保护，仅 DKF 内部访问
  • 快速认证上下文（会话密钥、计数器）：TEE 内存，断电后需重新标准认证
车端实现要点
  • 作为 Peripheral 角色，持续广播（周期 ≤ 100ms，建议 80ms）
  • 每 30 秒刷新加密配对码，更新广播数据包
  • 注销钥匙时更新 bleBroadcastKey，防止老设备接入
  • 支持多从节点（辅节点）信号采集，主节点负责认证和控车
  • UWB 测距：在标准/快速认证完成后，才可触发 UWB 测距请求（Type=0x01）
  • 离线场景：首次标准认证时，从设备获取证书链并本地验证

Android — BLE 扫描与配对码解密

// 扫描过滤：Service UUID = 0xFCD1
val filter = ScanFilter.Builder()
    .setServiceUuid(ParcelUuid.fromString("0000FCD1-0000-1000-8000-00805F9B34FB"))
    .build()

val callback = object : ScanCallback() {
    override fun onScanResult(callbackType: Int, result: ScanResult) {
        val adData = result.scanRecord?.getServiceData(
            ParcelUuid.fromString("0000FCD1-..."))
        if (adData != null && adData.size == 8) {
            val iv = adData.copyOfRange(0, 4)
            val cipherCode = adData.copyOfRange(4, 8)
            val plain = decryptPairingCode(bleBroadcastKey, iv, cipherCode)
            if (plain != null) connectToDevice(result.device)
        }
    }
}

// AES-128-CTR 解密配对码
fun decryptPairingCode(key: ByteArray, iv: ByteArray, cipher: ByteArray): ByteArray? {
    val nonce = MessageDigest.getInstance("SHA-256").digest(iv).copyOfRange(0, 12)
    val spec = IvParameterSpec(nonce + ByteArray(4)) // CTR 初始计数器
    val cipher128 = Cipher.getInstance("AES/CTR/NoPadding")
    cipher128.init(Cipher.DECRYPT_MODE, SecretKeySpec(key, "AES"), spec)
    return cipher128.doFinal(cipher)
}

Android — 认证回复消息构建（Type=0x02）

// 构建 7F2D 认证回复帧
fun buildAuthReply(
    keyId: ByteArray,       // 16B, tag 89h
    vehicleCmd: ByteArray,  // 控车指令 tag 57h (包含 7F70/7F73等)
    vehicleNonce: ByteArray,// 车端随机数 16B, tag 8Ah
    appNonce: ByteArray     // 安全应用随机数 16B, tag 9Ch
): ByteArray {
    // 1. 拼接签名输入
    val signInput = tlv(0x89, keyId) + tlv(0x57, vehicleCmd) +
                    tlv(0x8A, vehicleNonce) + tlv(0x9C, appNonce)

    // 2. TEE 签名（私钥不出 SE）
    val sig = teeSigning.signECDSA(keyId, signInput) // 64B, ECDSA-P256

    // 3. 组装 7F2D TLV
    val replyData = tlv(0x89, keyId) + tlv(0x57, vehicleCmd) +
                    tlv(0x9E, sig) + tlv(0x9C, appNonce)
    val payload = tlv(0x7F2D, replyData)

    // 4. 封装 BLE 帧头
    return buildBleFrame(version=0x01, type=0x02, status=0x0000, data=payload)
}

fun buildBleFrame(version: Byte, type: Byte, status: Short, data: ByteArray): ByteArray {
    val buf = ByteBuffer.allocate(6 + data.size).order(ByteOrder.BIG_ENDIAN)
    buf.put(version); buf.put(type); buf.putShort(status)
    buf.putShort(data.size.toShort()); buf.put(data)
    return buf.array()
}

iOS (Swift) — GATT 连接与 CCCD 订阅

class DKBLEManager: NSObject, CBCentralManagerDelegate, CBPeripheralDelegate {
    let DK_SERVICE_UUID = CBUUID(string: "FCD1")
    let DK_DATA_IN_UUID = CBUUID(string: "FFF1")
    let DK_DATA_OUT_UUID = CBUUID(string: "FFF2")

    func peripheral(_ peripheral: CBPeripheral,
                    didDiscoverCharacteristicsFor service: CBService, error: Error?) {
        for char in service.characteristics ?? [] {
            switch char.uuid {
            case DK_DATA_OUT_UUID:
                // 启用 Notification（CCCD）— 触发车端首次标准认证
                peripheral.setNotifyValue(true, for: char)
                dataOutChar = char
            case DK_DATA_IN_UUID:
                dataInChar = char
            default: break
            }
        }
    }

    func sendFrame(_ frame: Data) {
        guard let char = dataInChar else { return }
        // 按 MTU 分包发送
        let mtu = connectedPeripheral?.maximumWriteValueLength(for: .withResponse) ?? 200
        var offset = 0
        while offset < frame.count {
            let chunk = frame.subdata(in: offset ..< min(offset + mtu, frame.count))
            connectedPeripheral?.writeValue(chunk, for: char, type: .withResponse)
            offset += mtu
        }
    }
}
安全建议：生产环境中，所有涉及数字钥匙私钥的操作（ECDSA 签名、ECDH 密钥协商）必须在 TEE TA 或 SE Applet 内执行，私钥严禁导出到普通内存。bleBroadcastKey 和 IRK 也应通过 TEE KeyStore 或 SE 加密保护。
